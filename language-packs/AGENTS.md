# Czech translation maintenance

Read the repository-root `AGENTS.md` and `czech/README.md` first. This directory
contains a Czech translation backup on the user's fork. A GitHub backup does
not publish an official Pebble language pack.

## Files and dependencies

- `czech/tintin.po` is the editable source catalog. Preserve existing Czech
  wording unless fixing a specific error or a measured layout problem.
- `cs_CZ-with-fonts.pbl` is the installable output. `czech/firmware.po`,
  `czech/strings.mo`, `czech/coverage.json` and `czech/package-sha256.txt` are
  generated by `czech/build_pack.py`; regenerate them together.
- `pebbleos-translations/` is the official tools submodule. Initialize only this
  submodule for pack work, using the pinned revision. Do not commit a nested
  checkout or initialize all firmware submodules recursively.
- Install the small Python environment from `czech/requirements.txt` as
  documented in the README. GNU gettext is also required.
- `font-refinement/` contains matching font inputs and historical experiments.
  The current pack uses `czech/fonts/`. Keep the historical inputs needed by
  `prepare_matching_fonts.py`, `add_missing_dash.py` and the layout checker.

## Updating strings

1. Inspect Git status and remotes before updating firmware. Preserve the backup
   branch and local work; do not reset, overwrite or force-push it. Fetch and
   merge upstream changes on the working branch when an update is requested.
2. Refresh `czech/pebbleos.pot` from the universal current-firmware template.
   Follow `cmake/modules/gettext.cmake` and the firmware's source selection;
   exclude recovery apps and preserve contextual lookup keys. Record source
   inputs in `czech/pebbleos.pot.files` when extracting locally.
3. Merge with `msgmerge --no-fuzzy-matching`. Retain retired entries as obsolete
   history. Review additions rather than accepting fuzzy matches automatically.
4. Keep placeholders, context, plural forms, format flags, significant spaces
   and newlines intact. The Czech catalog uses three plural forms. The empty
   `TmplStringSing`, `TmplStringPlur` and `TmplStringMany` suffixes are deliberate.
5. Translate new wording concisely. Update `new-translations.csv` and the layout
   checks when the source template changes. Do not treat the existing 37-entry
   review matrix as coverage of future additions or all firmware strings.
6. Increase the numeric catalog revision for a changed installable pack and
   update `PO-Revision-Date`. The checked-in pack currently uses revision 42.
   Let `firmware_catalog()` arrange the watch headers; the watch reads only the
   first 399 header bytes. Preserve `Language: cs_CZ` and `Name: Čeština`.
7. Copy the final source PO to the submodule's optional `cs_CZ/tintin.po` working
   file when using its locale commands. The canonical backup stays in `czech/`.

## Fonts and layout

- Current built-in Gothic fonts cover Czech. Bitham, Roboto and Droid Serif
  still use the saved extensions for complete general-text coverage. Preserve
  matching glyph shapes; do not replace them with experimental accent variants.
- Subset only characters missing from each built-in font. Read font-slot order
  from the pinned tools; the current format has 29 font slots plus strings.
  Keep empty positional slots and verify all resource CRCs.
- Refresh built-in coverage from the matching firmware revision with the
  official extractor when font inputs change. General text styles need the
  Czech alphabet and actual translated characters. Numeric/subset fonts are
  specialized; full-alphabet gaps there do not establish a text-layout error.
- Check pixel widths using the actual font and screen's text box, including
  paused workout action bars, fixed buffers, wrapping and circular screens.
  The gauge has 62px bottom columns and the small countdown allows 68px.
- `layout-check/check_fit.py` measures the saved additions. Its unchanged time
  formats and units retain firmware formatting/wrapping. This is a measurement
  check, not a renderer or proof of every runtime state.
- For visible changes, use the repository's QEMU skill and capture real screens.
  Keep before/after evidence and state which boards and cases were checked.
  Do not describe QEMU or font measurements as physical-watch testing.

## Verification and saving work

Run the README's build, layout, gettext and checksum commands. Inspect font
coverage, ensure there are no fuzzy entries, and verify that active catalog
keys exactly match the source template. Run Ruff for changed Python scripts.
Check that the generated pack revision and digest describe the actual output.

Preserve catalogs, selected font inputs, build scripts, installable packs and
useful review evidence in Git. Keep build trees, flash images, ELF files, logs,
process IDs and sockets out. Stage explicit paths, inspect the staged diff,
follow the user's commit attribution/sign-off instructions, and run gitlint on
every new commit. Push this backup to the user's fork when requested.

Official distribution uses <https://translate.repebble.com/>. Human language
reviewers approve wording; publication requires the service's current approval
threshold, passing build checks, and approval of custom fonts and licenses.
Do not upload translations, publish a pack, open an upstream PR or message
maintainers unless the user asks for that action.
